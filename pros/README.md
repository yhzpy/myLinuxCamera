# 嵌入式 Linux 相机项目（video2lcd）面试拷打题库

> 本目录是针对 **myLinuxCamera / video2lcd** 项目定制的面试问答集，采用「面试官提问 + 参考答案 + 深挖追问」的形式，帮助你把这个项目在面试中讲透、扛住拷打。
>
> 项目一句话定位：**基于 V4L2 采集 USB 摄像头图像，经过格式转换（YUV/MJPEG→RGB）、缩放、居中合并后，通过 Framebuffer 实时显示到 LCD 屏幕的嵌入式 Linux C 应用。**

## 使用建议

1. **先背熟 01**：开场 2~3 分钟把项目讲清楚（背景、架构、数据流、你的工作、亮点），这是所有面试的第一步。
2. **按模块深挖 02~06**：面试官通常会挑一两个模块往死里问，务必理解「为什么这么设计」而不只是「代码怎么写」。
3. **重点看 07 的陷阱题**：里面列出了本项目代码中真实存在的可讨论点（如边界判断、内存管理、单线程撕裂、`main` 函数签名等），面试官很可能拿这些「挖坑」，提前准备能体现你的批判性思维和诚实态度。
4. **画图能力**：面试时能手画出「数据流水线」和「模块依赖图」会大大加分，图在 01 和 05 中都有。

## 快速记忆卡（30 秒电梯陈述）

> 我做了一个嵌入式 Linux 的相机实时显示项目。硬件是 imx6ull（ARM Cortex-A7）+ USB 摄像头 + LCD 屏。软件上，我用 **V4L2** 的 **mmap streaming** 方式采集摄像头数据，申请 4 个内核缓冲区轮转；采集到的帧格式可能是 **YUYV / MJPEG / RGB565**，通过一个**转换器管理框架**自动选择对应的转换器转成 LCD 的 RGB 格式（YUV 转换用**查找表**加速，MJPEG 用 **libjpeg** 解码）；如果图像比屏幕大，用**最近邻插值**等比缩放，再**居中合并**到 framebuffer，最后 `memcpy` 刷到 LCD 显存。整个项目用 **C 语言面向对象的思路**（函数指针结构体 + 链表注册）做模块解耦，用 **Kbuild 风格的递归 Makefile** 交叉编译。
